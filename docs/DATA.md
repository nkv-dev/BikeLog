# Data Storage & Repo Format

BikeLog is **local-first with a GitHub-of-record**. Your data exists in two places:

1. **Browser `localStorage`** (`bikelog_bikes`, `bikelog_fuel`, `bikelog_service`, `bikelog_issues`, `bikelog_settings`) — the fast offline cache the UI reads/writes.
2. **Your GitHub repo**, inside a `bikelog/` folder, as readable Markdown — the durable source of truth you can sync to and from.

> The app server stores **no user data**. Cloudflare KV only holds the user's OAuth token and selected-repo pointer.

## Repo layout

Inside the GitHub repo you select in Settings:

```
bikelog/
├── README.md                  # auto-generated dashboard index (bikes, totals, last service)
├── bikes/
│   └── <bike-slug>.md         # one Markdown file per bike, strict format (see below)
└── assets/
    └── <bike-slug>/
        └── photo-<timestamp>.<ext>   # uploaded photos
```

## Bike file format

Each `bikes/<slug>.md` uses a strict, human-readable structure with `<!-- bikelog:… -->`
markers so the app can round-trip it and you can still read/edit it on GitHub.

```markdown
# Duke 390

<sub>Auto-generated by BikeLog · edit with care, format is strict</sub>

<!-- bikelog:meta -->
- id: 5f8e2a
- name: Duke 390
- brand: KTM
- model: Duke 390 BS6
- year: 2021
- odometer: 12345
- fuelType: petrol
- createdAt: 2026-09-01T00:00:00.000Z
- photos: bikelog/assets/duke-390/photo-1.jpg,bikelog/assets/duke-390/photo-2.jpg

## Fuel
<!-- bikelog:fuel -->
### 2026-09-01 · 12345 km
- id: f1
- bikeId: 5f8e2a
- date: 2026-09-01T00:00:00.000Z
- odometer: 12345
- litres: 8.2
- pricePerLitre: 98.4
- totalCost: 620
- isFullTank: true
- station: HP

## Service
<!-- bikelog:service -->
### 2026-08-10 · 10000 km
- id: s1
- bikeId: 5f8e2a
- date: 2026-08-10T00:00:00.000Z
- odometer: 10000
- type: scheduled
- items: Oil change,Chain adjustment
- cost: 1200
- workshop: KTM Service Center
- nextServiceKm: 15000

## Issues
<!-- bikelog:issues -->
### 2026-08-15 · 10500 km
- id: i1
- bikeId: 5f8e2a
- date: 2026-08-15T00:00:00.000Z
- odometer: 10500
- title: Vibrating mirrors
- description: Excessive vibration above 80 km/h
- severity: low
- status: reported
- estimatedCost: 300
```

### Rules

- Each entry starts with a `### <YYYY-MM-DD> · <odometer> km` heading (only the date part is parsed for display; full ISO timestamps are stored in `date`).
- Properties are `- key: value` lines directly under the marker/heading.
- Optional properties (`station`, `notes`, `workshop`, `nextServiceKm`, `nextServiceDate`, `estimatedCost`, `actualCost`, `photos`) may be omitted.
- `items` is a comma-separated list.
- Keys match the app's types; unknown keys are ignored on read.
- Slug = lowercase name, non-alphanumerics → `-`, truncated to 60 chars (`duke-390-bs6` → `duke-390-bs6.md`).

## Sync behavior

- **Push** serializes all localStorage data into `bikelog/bikes/*.md` + `README.md` and commits to the selected repo's default branch. Markdown files for bikes that were deleted locally are removed from the repo so a later pull doesn't resurrect them.
- **Pull** reads every `bikelog/bikes/*.md`, parses each into a bike + its fuel/service/issue entries, and replaces localStorage. A missing `bikelog/` folder yields empty data (first-run friendly).
- **Photos** upload to `bikelog/assets/<slug>/` and are referenced from the bike file's `photos` list.

> **PR/merge caveat:** if you edit the Markdown by hand on GitHub, and the app also pushes, the commit uses GitHub API with the latest base tree — last-write-wins per file, not a merge. Keep edits lightweight.

## Offline / no backend notes

- Without a connected GitHub account the app is fully functional offline via localStorage.
- Connect + **Push data** to mirror to GitHub; **Pull data** to restore onto another device.
