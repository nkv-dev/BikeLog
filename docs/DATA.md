# Data Storage & Repo Format

BikeLog is **local-first with a GitHub-of-record**. Your data exists in two places:

1. **Browser `localStorage`** (`bikelog_bikes`, `bikelog_fuel`, `bikelog_service`, `bikelog_rides`, `bikelog_modifications`, `bikelog_checklists`, `bikelog_settings`) — the fast offline cache the UI reads/writes.
2. **Your GitHub repo**, inside a `bikelog/` folder, as readable Markdown — the durable source of truth you can sync to and from.

> The app server stores **no user data**. Cloudflare KV only holds the user's OAuth token and selected-repo pointer.

## Repo layout (0.0.2)

Inside the GitHub repo you select in Settings:

```
bikelog/
├── README.md                         # auto-generated dashboard index
├── bikes/
│   └── <bike-slug>/
│       ├── bike.md                   # bike profile (meta block only)
│       ├── fuel/
│       │   └── <YYYY-MM-DD>-<odo>.md # one file per fuel entry
│       ├── maintenance/
│       │   └── <YYYY-MM-DD>-<slug>.md# one file per service/repair/issue
│       ├── rides/
│       │   └── <YYYY-MM-DD>-<slug>.md# one file per ride
│       ├── modifications/
│       │   └── <YYYY-MM-DD>-<slug>.md# one file per modification
│       ├── checklists/
│       │   └── <name>.md             # one file per checklist (template)
│       └── media/
│           ├── bike/                 # profile photos
│           └── <category>/<YYYY>/<MM>/# photos attached to entries
└── assets/                           # (legacy 0.0.1 location — no longer written)
```

Each entry lives in its own file so GitHub shows clean, per-entry history.

## Entry & bike file format

Strict, human-readable structure with `<!-- bikelog:<category> -->` markers so the app
can round-trip it and you can still read/edit it on GitHub. Every file starts with a
`#` title line, optional `> description` line, then the marker and `- key: value` props.

`bike.md`:

```markdown
# Duke 390

<sub>Auto-generated by BikeLog · edit with care, format is strict</sub>

<!-- bikelog:bike -->
- id: 5f8e2a
- name: Duke 390
- brand: KTM
- model: Duke 390 BS6
- year: 2021
- odometer: 12345
- fuelType: petrol
- createdAt: 2026-09-01T00:00:00.000Z
- photos: bikelog/bikes/duke-390/media/bike/photo-1.jpg
```

A fuel entry (`fuel/2026-09-01-12345.md`):

```markdown
# Fuel · 2026-09-01 · 12345 km

<!-- bikelog:fuel -->
- id: f1
- bikeId: 5f8e2a
- date: 2026-09-01T00:00:00.000Z
- odometer: 12345
- litres: 8.2
- pricePerLitre: 98.4
- totalCost: 620
- isFullTank: true
- station: HP
- notes: highway
```

A service/repair/issue entry (`maintenance/2026-08-10-duke-390.md`):

```markdown
# Service · 2026-08-10 · 10000 km

<!-- bikelog:maintenance -->
- id: s1
- bikeId: 5f8e2a
- date: 2026-08-10T00:00:00.000Z
- odometer: 10000
- type: scheduled
- items: Oil change,Chain adjustment
- cost: 1200
- workshop: KTM Service Center
- nextServiceKm: 15000
- nextServiceDate: 2027-02-10
```

Issues are maintenance entries with `type: issue` plus the issue fields:

```markdown
# Issue · 2026-08-15 · 10500 km

<!-- bikelog:maintenance -->
- id: i1
- bikeId: 5f8e2a
- date: 2026-08-15T00:00:00.000Z
- odometer: 10500
- type: issue
- items: 
- cost: 300
- title: Vibrating mirrors
- description: Excessive vibration above 80 km/h
- severity: low
- status: reported
- estimatedCost: 300
- actualCost: 400
```

Ride (`rides/2026-09-03-duke-390.md`), modification
(`modifications/2026-09-04-duke-390.md`), and checklist (`checklists/pre-ride.md`):

```markdown
# Ride · 2026-09-03
<!-- bikelog:ride -->
- id: r1
- bikeId: 5f8e2a
- date: 2026-09-03T00:00:00.000Z
- route: Bangalore → Mysore → Bangalore
- distanceKm: 245.5
- odometer: 12300
- avgSpeedKmh: 68
- notes: rain

# Mod · 2026-09-04
<!-- bikelog:modification -->
- id: m1
- bikeId: 5f8e2a
- date: 2026-09-04T00:00:00.000Z
- title: LED headlamp upgrade
- description: 60W LED set, better throw at night
- cost: 3200
- installedBy: Amazon garage

# Pre-ride check
<!-- bikelog:checklist -->
- id: c1
- bikeId: 5f8e2a
- name: Pre-ride check
- createdAt: 2026-09-01T10:00:00.000Z
- items: Helmet & gloves,Air pressure,Chain lube,Mirrors aligned
```

### Rules

- The first `<!-- bikelog:<category> -->` marker classifies the file (`bike` | `fuel` |
  `maintenance` | `ride` | `modification` | `checklist`).
- Properties are `- key: value` lines directly under the marker.
- The `#` heading + `> description` line are display-only (ignored on parse).
- Optional props (`station`, `notes`, `workshop`, `nextServiceKm`, `nextServiceDate`,
  `odometer`, `avgSpeedKmh`, `cost`, `description`, `installedBy`, `severity`, `status`,
  `estimatedCost`, `actualCost`, `photos`) may be omitted.
- `items` is a comma-separated list.
- Keys match the app's types; unknown keys are ignored on read.
- Slug = lowercase name, non-alphanumerics → `-`, truncated to 60 chars.
- Checklist names become filenames via `slugify`; duplicate names get an `-<id5>` suffix.

## Sync behavior

- **Auto-sync (0.0.2):** once a repo is selected and you're connected, every local change
  (add/edit/delete) auto-pushes to GitHub after a 5s debounce. The header sync button forces
  a push immediately. Connect + repo selection happen once in Settings.
- **Push** serializes all localStorage data into per-entry `.md` files + `README.md` and
  commits to the selected repo's default branch. Files (including legacy single-file bikes)
  no longer present locally are removed so a later pull doesn't resurrect them.
- **Pull** reads every `bikelog/bikes/<slug>/**` markdown file, parses into the six
  collections, and replaces localStorage. A missing `bikelog/` folder yields empty data
  (first-run friendly).
- **Migration:** legacy 0.0.1 `bikes/<slug>.md` single files (meta/fuel/service/issues
  sections) are parsed on pull into the new collections; issues become maintenance entries
  of type `issue`. Legacy `bikelog_issues` localStorage is migrated once too.
- **Photos** upload to `bikelog/bikes/<slug>/media/` and are referenced in `bike.md`'s
  `photos` list.

> **PR/merge caveat:** if you edit the Markdown by hand on GitHub and the app also pushes,
> the commit uses GitHub API with the latest base tree — last-write-wins per file, not a
> merge. Keep edits lightweight.

## Offline / no backend notes

- Without a connected GitHub account the app is fully functional offline via localStorage.
- Connect once in Settings, then auto-sync keeps GitHub mirrored automatically.
